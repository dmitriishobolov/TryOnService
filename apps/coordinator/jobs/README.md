# Coordinator Jobs

Папка для доменной логики jobs: создание задач, in-memory хранение состояния, переходы статусов, ошибки и метаданные результата.

## Роль jobs

Job описывает один запрос пользователя на AI-примерку. Coordinator является источником правды по состоянию job, а worker только сообщает о ходе выполнения.

## Базовые статусы

- `queued` - задача создана и ожидает назначения; в текущем direct-dispatch flow почти не используется.
- `assigned` - coordinator выбрал worker и выдал клиенту assignment.
- `running` - worker начал обработку.
- `succeeded` - обработка завершилась успешно.
- `failed` - обработка завершилась ошибкой.
- `cancelled` - задача отменена.

## Что хранить в job

- идентификатор job;
- идентификатор клиента или интеграции;
- входной payload по контракту;
- текущий статус и история переходов;
- назначенный worker, если он есть;
- последнюю ошибку;
- callback URL клиента, если результат должен уйти напрямую клиентской интеграции.

## Правила

- Переходы статусов должны быть явными и проверяемыми.
- Повторное обновление одного и того же статуса не должно ломать job.
- В jobs не должно быть кода вызова AI API - это ответственность worker.
